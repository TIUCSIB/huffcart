# Design

## Context

虚拟手柄现状：竖屏 `SkinPadPanel`（素材皮肤：挖孔底图 + 独立按键精灵，十字键按触点主导轴判向、滑动换向），横屏 `PadControlsOverlay`（Canvas 半透明控件）。手感基建（弹簧下沉/回弹、变暗、触觉反馈）已由 `pad-feel` 落地。输入链路终点是 `(RetroButton, Boolean)` 回调，核心只有 8 个数字键、每帧轮询键位状态（见 proposal Why）。

设置侧现状：`KeyMappingStore` 用 SharedPreferences 存按键映射（项目约定：不为少量数据引入 DataStore）；`SettingsScreen` → 「按键设置」→ `KeyMappingScreen`（映射行 + 恢复默认）。游戏进行中无法到达设置页（游戏屏为独立全屏路由，顶栏菜单仅存/读/快进/退出）。

## Goals / Non-Goals

**Goals:**

- 摇杆形态在竖屏皮肤面板与横屏浮层都可用，观感与现有皮肤一致（深灰 + 红高亮）
- 方向判定（死区、迟滞、8 向扇区）抽成纯函数，可脱离 Android 单测
- 十字键 / 摇杆切换持久化，默认十字键，行为对核心完全透明

**Non-Goals:**

- 不输出模拟量（核心无模拟轴）；不做灵敏度/死区自定义设置
- 不在游戏内提供切换入口；不改 A/B/SELECT/START；不触碰皮肤素材与切片脚本
- 不为摇杆新增竖屏底图（用代码绘制底座覆盖挖孔，见决策 5）

## Decisions

1. **摇杆是纯 UI 层映射，输出仍是 `RetroButton` 组合**。推杆向量 → 方向集合（0–2 个），集合变化时按「先抬旧、后按新」的差集顺序发回调——与皮肤十字键现有滑动换向的发序一致，核心无感知。备选「给核心加模拟轴」被否：改动面大且对 NES 游戏无收益。

2. **方向判定抽纯函数 `JoystickMath`**（新文件 `ui/game/JoystickMath.kt`）：输入归一化偏移 `(x, y)`（除以底座半径），输出 `Set<RetroButton>`。规则：
   - 距离死区 0.25，未激活时低于它返回空集；**已激活后退出阈值降为 0.20**（距离迟滞，防边界抖动）；
   - 角度按 8 扇区（边界 ±22.5°），**当前方向的扇区外扩 5°（±27.5°）才换向**（角度迟滞）；
   - 换向无方向记忆跨手势——每次手势从空集开始。
   备选「四向（无斜向）」被否：魂斗罗 45° 射击等场景需要斜向。

3. **`JoystickControl`（PadControls.kt 内）视觉与手势**：Canvas 画底座环（凹槽深灰 `DpadRecess` + 细描边）与摇杆帽（径向渐变深灰球 + 高光）；推向某方向时帽缘对应侧红色高亮（`HcPadRed`，延续"按下红"语言）。手势：`pointerInput` + `awaitEachGesture`，按住期间**帽位置跟手即时更新（不走动画）**，仅松手回中用 `animateDpAsState` 弹簧（MediumBouncy，与现有手感同参）；首次按下触觉反馈一次，换向不震（与现有一致）。帽最大偏移 0.55R。`translucent` 参数供横屏半透明。备选「帽位移也用弹簧」被否：跟手延迟会直接毁掉摇杆手感。

4. **设置存 `ControlSchemeStore`（SharedPreferences）**：`enum ControlScheme { DPAD, JOYSTICK }`，键 `virtual_pad_style`，默认 `DPAD`，沿用 `KeyMappingStore` 轻量约定。`GameScreen` 进入时读取一次——设置页在游戏中不可达，会话内固定是可接受简化。备选 DataStore/Flow 实时观察被否：收益为零。

5. **竖屏摇杆覆盖十字键挖孔**：JOYSTICK 形态下不画 `skin_dpad` 精灵，改为在同一孔位区放 `JoystickControl`，底座为**不透明深灰圆盘且直径 ≥ 十字包络（0.63 × 精灵区）**，完全遮蔽底图十字挖孔与凹槽；B/A/SELECT/START 精灵照旧。备选「重切片一张带摇杆的底图」被否：要动素材脚本，且切换形态时需换底图。

6. **入口放按键设置页顶部**：`KeyMappingScreen` 在映射行上方加「虚拟手柄样式」行（显示当前值），点按弹单选 AlertDialog（复用 `SettingsScreen`「关于」的对话框模式），选完即存。备选放 `SettingsScreen` 一级行被否：输入类设置集中一处、且该页有控制布局预览可联动。

7. **归档顺序**：本 change 的 delta 文本已合并在途 `pad-feel` 对「虚拟手柄输入」的全部修改（弹簧手感 + 皮肤面板描述）。**建议先归档 `pad-feel`、再归档本 change**——两 delta 改同一 requirement，后归档者全文生效，合并文本保证无信息丢失。

8. **十字键与 SELECT/START 改代码绘制（二轮，用户实测反馈）**：素材切片把凹槽环/挖孔环烘焙进了精灵图（四角虽透明），按压位移（十字偏移、胶囊下沉）会让烘焙环与底图挖孔错位出「双圈」——合成图复现确认；且皮肤十字键主导轴判向无斜向。切片无法裁剪规避（臂会触到裁剪边被切平）、用户无更优素材，故两者改 Canvas 绘制（配色取素材实测常量）：凹槽固定不动、十字/胶囊按压位移，十字手势改 `JoystickMath` 触点角度判向（8 向含斜向，死区+迟滞），横屏 `DpadControl` 同步换用同一手势保持两端行为一致。备选「精灵按凹槽裁圆」被否：十字臂端会被裁平。

9. **控制面板整体弃图、全代码绘制（三轮，用户反馈「突兀」）**：二轮把十字键/胶囊改成代码绘制后，扁平控件叠在带纹理的底图上观感割裂；用户拍板不再用底图展示。面板底（深色圆角 Canvas）+ 十字键（DpadControl）+ A/B（RoundPadButton 渐变红球，即最初 asset 设计的代码版，尺寸随面板高度缩放）+ SELECT/START（Pill，文字改像素字体）全部代码绘制，横竖屏同一设计语言；skin_*.png 素材不再被面板引用（文件保留）。

## Risks / Trade-offs

- [摇杆叠在挖孔底图上观感突兀] → 底座不透明圆盘 + 细描边兜底；实机截图验收专门核对竖屏摇杆观感，不行再补一张带摇杆的底图切片（局部返工，不影响其他任务）
- [迟滞参数手感不佳（死区太大/换向迟钝）] → 参数集中在 `JoystickMath` 顶部常量，单测覆盖边界后仍可调；验收时实机试玩超级玛丽确认走位/斜向
- [多指操作：一只手推杆、另一只手按 A/B] → 摇杆命中区是独立 `pointerInput` 区域，与皮肤单键互不干扰；手势内仅追踪首个按下的指针（`awaitFirstDown` 后以该指针位置判向），其余指针被忽略——与现有皮肤十字键行为一致

10. **真机反馈调优（四轮）**：① 十字键点按无响应——手势原先只在 move 事件判向，快速点按（down+up 无 move）永不生效，且摇杆 0.25 死区令十字中心大片区域无反应；改为 down 落点即判定，十字键专用死区 0.12/0.10（`JoystickMath.directions` 增加死区参数）。② 高亮块过长——半臂红块改臂端短块（env/4，覆盖箭头区），十字下压加深至尺寸 4.5%。③ 立体感——A/B 球体加上缘受光/下缘入影渐变与随尺寸缩放的深度投影（`depth` 参数），按压下沉至与投影齐平；胶囊同样加投影/顶光/下沉 3dp。④ 布局——面板加高（386/186 → 386/200）压缩内容区与控制区的视觉距离并容纳更大按键（十字键/A-B 0.86h/0.38h、胶囊 78×30 间距 18dp）；SELECT/START 移至右下（B/A 正下方），真机上不再与十字键拥挤。

11. **布局与高亮微调（五轮，真机反馈）**：① 面板再加高（386/200 → 386/215）。② SELECT/START 回到面板底部居中——右下布局被用户否决；为保命中不冲突，十字键改为靠左上（TopStart，0.78h）+ 圆形命中裁剪，几何上胶囊左缘在十字命中圆外。③ A 键高于 B 键的错位加大（0.09 → 0.20 倍键径，贴近 asset 设计）。④ 十字键高亮回到「覆盖整条半臂」（与臂身同宽同长、圆角一致）——四轮的臂端短块被用户否决（未覆盖满、观感突兀）。
